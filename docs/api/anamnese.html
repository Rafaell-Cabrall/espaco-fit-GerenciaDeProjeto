Anamnese: guia para o front

Formulário do primeiro acesso do aluno · Versão 1 · 16/09/2026
Vale a partir do merge do PR da anamnese na main.

Resumo

  • São duas rotas: GET para ler e PUT para responder ou atualizar. As duas usam o id do aluno logado, que vem de useAuth().user.id.
  • Se o GET devolver null, o aluno ainda não respondeu: abra o formulário antes de liberar a Home.
  • O consentimento de uso dos dados de saúde é obrigatório (LGPD). Sem ele a API recusa o envio.
  • Tipos, opções e mensagens vêm de @espacofit/shared. Não redeclarar no app.

1. Onde entra no app

  1. O aluno faz login, ou abre o app já logado, e cai no grupo (aluno).
  2. Antes de mostrar a Home, chame GET /anamnesis/:id com o user.id.
  3. Se vier null, abra o formulário de anamnese. Se vier um objeto, siga para a Home.
  4. No envio do formulário, chame PUT /anamnesis/:id. Com 200, siga para a Home.

Só o aluno passa por esse fluxo. Instrutor e admin não respondem anamnese.

// null = ainda não respondeu: abrir o formulário antes da Home
import { anamnesisSchema } from '@espacofit/shared'
import { api } from '../../api/client'

export const buscarAnamnese = (studentId: string) =>
  api(`/anamnesis/${studentId}`, anamnesisSchema.nullable())

Erro de rede não é null

Só a API devolve null. Se a chamada falhar por falta de internet, mostre o erro com "Tentar de novo" em vez de abrir o formulário. Caso contrário, um aluno que já respondeu seria mandado de volta para a anamnese.

Os valores das escolhas são o próprio texto exibido. Monte as opções direto do schema: FitnessLevel.options, Goal.options e WeeklyFrequency.options. Assim, se uma opção mudar, o app acompanha sem alteração.

Rótulos e opções seguem a tela Evolução > Anamnese do protótipo. Se o design da tela do primeiro acesso mudar alguma opção, avise o back: a mudança é feita no schema.

Valide no app antes de enviar

Se o envio for inválido, a API responde só 400 "Dados inválidos", sem o texto de cada campo. As mensagens para o aluno vêm do anamnesisInputSchema no app, principalmente a do consentimento.

// screens/Anamnese/index.tsx
import { type AnamnesisInput, anamnesisInputSchema, anamnesisSchema } from '@espacofit/shared'
import { api, ApiError } from '../../api/client'

async function enviar(studentId: string, values: AnamnesisInput) {
  const check = anamnesisInputSchema.safeParse(values)
  if (!check.success) return setErro(check.error.issues[0].message)
  try {
    await api(`/anamnesis/${studentId}`, anamnesisSchema, { method: 'PUT', body: check.data })
    // navegar para a Home
  } catch (e) {
    if (e instanceof ApiError) setErro(e.message)
  }
}

3. Referência das rotas

Base: EXPO_PUBLIC_API_URL. As duas rotas exigem login; o cliente api() já envia o token e o renova. Erros vêm em {"error": "…"}.

Enviar de novo substitui as respostas e renova consentAt e updatedAt. É a mesma rota do futuro botão "Atualizar Anamnese".

Campos da resposta calculados pela API

CampoSignificado
consentAtData e hora, em ISO 8601 UTC, do último envio com a autorização marcada.
updatedAtData e hora da última resposta. Serve para "Anamnese atualizada em 16/09/2026".
outdatedtrue após 60 dias sem atualizar. Só sinaliza e não bloqueia nada. É usado na aba Evolução, fora do primeiro acesso.

4. Checklist do app

  • Ao entrar no grupo (aluno), buscar a anamnese antes de liberar a Home.
  • null abre o formulário. Erro de rede mostra "Tentar de novo" e não abre o formulário.
  • Opções de nível, objetivo e frequência montadas a partir de .options dos schemas.
  • Checkbox de autorização dos dados de saúde, validado com anamnesisInputSchema antes do envio.
  • Campos de texto opcionais podem ir vazios ou ser omitidos.
  • Envio com sucesso leva para a Home.
  • O :studentId das rotas é sempre o user.id do aluno logado.

5. Rodando local
