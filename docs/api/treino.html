Ficha e treino: guia para o front

Home, Meus Treinos e execução do treino (aluno) · Montagem da ficha (instrutor, Sprint 2) · Versão 1 · 16/09/2026
Vale a partir do merge do PR #7 na main. Rode npm run db:migrate e npm run db:seed depois do pull.

Resumo

  • Uma chamada só alimenta a Home e Meus Treinos: GET /plans/student/:id. Ela já traz o treino do dia, o tempo estimado, a última carga de cada exercício e o GIF.
  • Executar o treino usa 5 rotas de /sessions: iniciar, concluir série, desmarcar série, finalizar e sair do treino.
  • O id do item da ficha (exercises[i].id) é o que vai ao registrar série. O exercises[i].exercise.id é o do exercício na biblioteca e não serve para isso.
  • Nada é calculado no app: treino do dia, "~29 min" e carga sugerida vêm prontos. Tipos vêm de @espacofit/shared.

Três cuidados

  • Erro de rede não é null. null vem só da API e abre o estado vazio ("ficha ainda não disponível", texto do design). Sem internet, mostre a ficha do cache ou "Tentar de novo".
  • mediaUrl vale 1 hora. Não salve a URL. Se o GIF falhar ao carregar, refaça a consulta da ficha. Hoje todos vêm null porque os GIFs ainda não foram enviados: use um placeholder.
  • Treino do dia só avança depois de finalizar. Ao receber 200 no finish, invalide ['plan', studentId] para a Home mostrar a próxima divisão e as cargas novas.

3. Execução do treino

  1. Iniciar (em qualquer aba, não só a do dia): gere um id no aparelho e chame POST /sessions com { id, divisionId }. Guarde o id do treino no estado da tela.
  2. Concluir série: PUT /sessions/:id/sets com o id do item, o número da série (começa em 1) e a carga. Depois dispare o cronômetro de descanso com restSeconds.
  3. Corrigir a carga de uma série já concluída: o mesmo PUT com a carga nova. Não cria outra série.
  4. Desmarcar série: DELETE /sessions/:id/sets/:itemId/:setNumber.
  5. "Nota do exercício": guarde no estado da tela. As notas vão todas juntas ao finalizar.
  6. Finalizar Treino: POST /sessions/:id/finish com { notes }. Com 200, abra a tela de treino concluído. Com 422, abra o pop-up "Nenhum exercício concluído".
  7. "Sair do treino" no pop-up: DELETE /sessions/:id e volte para a tela anterior. O treino sem série é descartado e não conta como dia treinado.
// api/sessions.ts — rotas 204 usam z.undefined()
import { type FinishSessionInput, sessionSchema, setLogSchema, type SetLogInput } from '@espacofit/shared'
import * as Crypto from 'expo-crypto' // npx expo install expo-crypto
import { z } from 'zod'
import { api } from './client'

export const iniciarTreino = (divisionId: string) =>
  api('/sessions', sessionSchema, { method: 'POST', body: { id: Crypto.randomUUID(), divisionId } })

export const concluirSerie = (sessionId: string, body: SetLogInput) =>
  api(`/sessions/${sessionId}/sets`, setLogSchema, { method: 'PUT', body })

export const desmarcarSerie = (sessionId: string, itemId: string, setNumber: number) =>
  api(`/sessions/${sessionId}/sets/${itemId}/${setNumber}`, z.undefined(), { method: 'DELETE' })

export const finalizarTreino = (sessionId: string, body: FinishSessionInput) =>
  api(`/sessions/${sessionId}/finish`, sessionSchema, { method: 'POST', body })

export const sairDoTreino = (sessionId: string) =>
  api(`/sessions/${sessionId}`, z.undefined(), { method: 'DELETE' })
// screens/ExecucaoTreino — item = division.exercises[i]
await concluirSerie(sessao.id, {
  divisionExerciseId: item.id,        // id do item da ficha, NÃO item.exercise.id
  setNumber: 2,                       // "Série 2"
  loadKg: carga === '' ? null : Number(carga.replace(',', '.')),
})

try {

} catch (e) {

}

Contador "0/5 exercícios concluídos · 0 séries"

Monte a partir das séries que o app já marcou (ou de session.sets): séries = total de séries concluídas; exercício concluído = item com todas as item.sets séries marcadas.

O treino em andamento fica no app

Não existe rota para buscar um treino aberto. Se o app fechar no meio do treino, só o que estiver salvo no aparelho volta. O que a API já garante é que repetir qualquer chamada não duplica nada, então uma chamada que falhou por rede pode ser reenviada igual:

  • POST /sessions com o mesmo id devolve o mesmo treino.
  • PUT .../sets repetido atualiza a mesma série. DELETE de série já desmarcada responde 204.
  • Finalizar de novo devolve o treino já finalizado. Sair de um treino já descartado responde 204.

Mantenha a ordem: iniciar, séries, finalizar. A fila offline completa, com o banner "Modo Offline", é da Sprint 3.

5. Instrutor: montar a ficha (Sprint 2)

As telas do instrutor entram na Sprint 2, mas as rotas já funcionam e são usadas na demo da Sprint 1 via Insomnia/Bruno.

  1. Criar Nova Ficha: antes de abrir a tela, chame GET /anamnesis/:studentId. Se vier null, mostre o alerta de bloqueio (RN05). A API também recusa com 409.
  2. Biblioteca: GET /exercises lista todos, ordenados por grupo e nome, para o seletor de exercícios.
  3. Salvar: POST /plans cria a ficha como rascunho (DRAFT). O aluno ainda não vê.
  4. Ajustar o rascunho: PUT /plans/:id substitui todas as divisões.
  5. Publicar Ficha: POST /plans/:id/publish. A ficha vira ACTIVE e a anterior do aluno passa a EXPIRED.
// corpo de POST /plans (createPlanSchema). A ordem dos arrays é a ordem na tela.
{
  "studentId": "cmtvibwqv0003i3x0micjs5wl",
  "divisions": [
    {
      "label": "A",
      "title": "Peito & Tríceps",
      "exercises": [
        { "exerciseId": "cmtvibwrk0008i3x0qappqxq7", "sets": 4, "reps": "8-10", "restSeconds": 90, "targetLoadKg": 10 },
        { "exerciseId": "cmtvibwrk000bi3x051slwa05", "sets": 3, "reps": "12" }
      ]
    }

Regras: 1 a 7 divisões; label até 3 caracteres; title até 60; ao menos 1 exercício por divisão; sets de 1 a 20; reps como "12" ou "8-10"; restSeconds de 0 a 600 (padrão 60); targetLoadKg opcional. Valide com createPlanSchema no app: o 400 traz o texto de cada campo em issues[].message, mas a mensagem em error é só "Dados inválidos".

Editar a ficha que o aluno já usa

PUT só vale para rascunho (409 na ficha ativa), porque a ficha ativa guarda o histórico de cargas. Para "editar" a ativa: copie as divisões dela para o formulário, envie como POST /plans e publique. A anterior expira e o histórico fica.

// Plan (resposta) → divisions do POST /plans. Serve também para "usar modelo".
const paraEdicao = (plan: Plan): DivisionInput[] =>
  plan.divisions.map((d) => ({
    label: d.label,
    title: d.title,
    exercises: d.exercises.map((e) => ({
      exerciseId: e.exercise.id, sets: e.sets, reps: e.reps,
      restSeconds: e.restSeconds, targetLoadKg: e.targetLoadKg,
    })),
  }))

6. Checklist do app (aluno)

  • Home e Meus Treinos usam a mesma query ['plan', user.id].
  • null mostra o estado vazio; erro de rede mostra o cache ou "Tentar de novo".
  • Selo "Hoje" e card do treino do dia a partir de todayDivisionId.
  • Campo de carga preenchido com lastLoadKg ?? targetLoadKg, aceitando vírgula e vazio (null).
  • GIF com placeholder quando mediaUrl é null; URL não é salva.
  • Id do treino gerado com expo-crypto e enviado no POST /sessions.
  • Séries registradas com item.id, nunca item.exercise.id.
  • Cronômetro de descanso com restSeconds depois de concluir a série.
  • 422 no finalizar abre o pop-up; "Sair do treino" chama DELETE /sessions/:id.
  • Depois de finalizar, invalidar a ficha para o treino do dia avançar.
