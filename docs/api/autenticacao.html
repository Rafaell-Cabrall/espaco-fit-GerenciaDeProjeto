Autenticação: guia para o front

Login, cadastro, recuperação de senha e sessão · Versão 1 · 11/09/2026
Vale a partir do merge do PR de autenticação na main.

Resumo

  • Todas as telas do Figma de login, cadastro e "Esqueci a senha" já têm rota pronta na API.
  • Tipos e validações vêm de @espacofit/shared. Não redeclarar no app.
  • O cliente api() em src/api/client.ts já renova o token sozinho e transforma qualquer erro em ApiError com a mensagem pronta para exibir.
  • Duas mudanças no app: "Sair da conta" passa a chamar a API e "Reenviar código" tem um timer de 60 s imposto pelo servidor.

1. Como a sessão funciona

TokenValidadePara que serve
Access token15 minutosVai no cabeçalho Authorization: Bearer … de toda rota protegida.
Refresh token30 diasSó serve para pedir um par novo em POST /auth/refresh.
  1. Ao abrir o app, o AuthProvider chama GET /auth/me.
  2. Se a API responder 401, o cliente chama /auth/refresh uma vez e repete a requisição.
  3. Se o refresh também falhar, o cliente apaga os tokens e o usuário fica null: o app volta para o login.

O que encerra a sessão na hora, em todos os aparelhos: sair da conta, redefinir a senha e ter a conta desativada pela recepção. Nesses casos, a próxima requisição recebe 401 e o fluxo acima leva ao login.

"Lembrar Acesso" é decisão só do app: marcado, guarda os tokens no SecureStore como hoje; desmarcado, mantém em memória e pede login ao reabrir. A API não muda.

2. Fluxos por tela

Criar conta → Conta Criada com Sucesso

  1. Valide o formulário com registerSchema. "Confirmar senha" é só do app; a API ignora campos extras.
  2. Envie POST /auth/register. A resposta traz tokens, mas o Figma leva para "Ir para o Login": pode ignorá-los.
  3. Se vier 409, mostre a mensagem "E-mail já cadastrado".
// screens/Cadastro/index.tsx
import { authResponseSchema, registerSchema } from '@espacofit/shared'
import { z } from 'zod'
import { api, ApiError } from '../../api/client'

export const cadastroForm = registerSchema
  .extend({ confirmPassword: z.string() })
  .refine((v) => v.password === v.confirmPassword, {
    path: ['confirmPassword'],
    message: 'As senhas não conferem',
  })

async function criarConta(values: z.infer<typeof cadastroForm>) {
  try {
    await api('/auth/register', authResponseSchema, { method: 'POST', body: values, auth: false })
    // navegar para "Conta Criada com Sucesso!"
  } catch (e) {
    if (e instanceof ApiError) setErro(e.message) // "E-mail já cadastrado"
  }
}

Seja Bem-vindo (login)

  1. Use o login() do useAuth(). Ele já salva os tokens e preenche o usuário.
  2. Em erro, mostre e.message como veio. As três mensagens possíveis estão na seção 3.
  3. Depois do login, redirecione pelo user.role: ALUNO, INSTRUTOR ou ADMIN.

Esqueci a senha → Verifique seu e-mail → Criar nova senha → Senha atualizada

  1. Esqueci minha senha: POST /auth/forgot-password. A resposta é 204 exista ou não a conta, então avance sempre para a próxima tela.
  2. Verifique seu e-mail: mostre o e-mail digitado e inicie o timer "Reenviar código em 01:00". O botão "Reenviar código" chama a mesma rota quando o timer zerar.
  3. Verificar Código: POST /auth/verify-reset-code com e-mail e os 6 dígitos. 204 abre "Criar nova senha"; 400 mostra "Código inválido ou expirado".
  4. Redefinir Senha: POST /auth/reset-password com e-mail, o mesmo código e a nova senha. Guarde e-mail e código no estado da navegação entre as telas.
  5. Senha atualizada: botão "Ir para o Login". Qualquer sessão antiga dessa conta foi encerrada.

Regras do código que a tela precisa refletir

  • Vale por 10 minutos e aceita 5 conferências no total, somando "Verificar Código" e "Redefinir Senha". O fluxo normal gasta 2.
  • Estourou as tentativas ou o prazo: a API responde 400 e só um código novo resolve. Ofereça "Reenviar código".
  • Reenviar exige 60 s entre pedidos e no máximo 5 por hora. Antes disso a API responde 429 com a espera na mensagem.
  • O e-mail chega com o assunto "Seu código de recuperação — Espaço Fit". Vale dizer ao aluno para olhar o spam.
// respostas 204 não têm corpo: passe z.undefined() como schema
await api('/auth/forgot-password', z.undefined(), { method: 'POST', body: { email }, auth: false })
await api('/auth/verify-reset-code', z.undefined(), { method: 'POST', body: { email, code }, auth: false })
await api('/auth/reset-password', z.undefined(), {
  method: 'POST',
  body: { email, code, password },
  auth: false,
})

Sair da conta

O modal "Tem certeza que deseja sair da conta?" chama o logout() do useAuth(). Ele precisa avisar a API antes de apagar os tokens:

// src/auth.tsx
const logout = async () => {
  // sem internet, sai mesmo assim; a sessão expira sozinha
  await api('/auth/logout', z.undefined(), { method: 'POST' }).catch(() => {})
  await tokens.clear()
  setUser(null)
}

5. Checklist do app

  • logout() em src/auth.tsx chama POST /auth/logout antes de apagar os tokens.
  • Timer de 60 s em "Verifique seu e-mail", reiniciado a cada envio com sucesso.
  • Rotas com resposta 204 chamadas com z.undefined().
  • Erros exibidos com e.message de ApiError, sem traduzir status no app.
  • E-mail e código guardados na navegação entre "Verifique seu e-mail" e "Criar nova senha".
  • Cadastro leva para "Conta Criada com Sucesso!" e depois para o login.
  • Após o login, redirecionar pela role para os grupos (aluno), (instrutor) ou (admin).

6. Rodando local

  • Três terminais: npm run dev:api, npm run dev:worker e npm run dev:mobile. O worker é quem envia o e-mail.
  • Sem SMTP no .env, o e-mail não sai: ele aparece no terminal do worker com o código.
  • No celular, EXPO_PUBLIC_API_URL precisa ser o IP da máquina na rede, não localhost.
  • Usuários de teste do npm run db:seed, todos com a senha Senha123: joao@email.com (aluno), instrutor@espacofit.com e admin@espacofit.com.
  • Depois de atualizar a main, rode npm run db:migrate e faça login de novo: tokens antigos passam a ser recusados.
